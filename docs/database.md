# Хранение данных

Рабочее хранилище — Supabase Postgres. Бот хранит только Telegram ID, ID раскидки, тип отметки (`favorite` / `mastered`) и время добавления. Тексты сообщений, имена и токен бота в базу не записываются.

## Что подключено

- Проект: `jpwbzgqhqcyuffycxfcq` (существующий проект владельца).
- Таблица: `public.cs2_lineup_marks`; остальные таблицы проекта не используются и не изменяются.
- Серверная функция: `https://jpwbzgqhqcyuffycxfcq.supabase.co/functions/v1/cs2-lineup-store`.
- Схема: [database/supabase.sql](../database/supabase.sql).
- Интерфейс приложения: [src/lib/store.ts](../src/lib/store.ts).

В Vercel заданы серверные переменные `SUPABASE_URL` и `SUPABASE_STORE_SECRET`. У них нет префикса `NEXT_PUBLIC_`. Секрет — случайное значение с энтропией 256 бит. В исходниках функции находится только его SHA-256, позволяющий проверить запрос без публикации ключа. Полный ключ Supabase service role не передаётся в Vercel: функция использует встроенную серверную переменную Supabase.

Функция принимает только POST с заголовком `x-cs2-store-key`. Проверяет ключ, действие, Telegram ID, тип отметки, ID раскидки и размер запроса. Доступ к данным пользователя разрешён только серверу бота после проверки секрета Telegram webhook. Браузер не может выбирать Telegram ID и вызывать хранилище напрямую. Флаг `verify_jwt=false` используется потому, что функция выполняет собственную проверку серверного ключа.

На таблице включён RLS и отозваны все права у `PUBLIC`, `anon` и `authenticated`. RLS-политик для клиентов намеренно нет: доступ закрыт по умолчанию. `service_role` имеет только SELECT, INSERT и DELETE для этой таблицы. Первичный ключ `(telegram_id, grenade_id, kind)` одновременно поддерживает выборку по пользователю и защищает от дубликатов. Повторная установка одного значения безопасна; переключения выполняются как явные «включить» / «выключить».

`/delete_me` удаляет все отметки текущего пользователя. История персональных данных отдельно не ведётся. Supabase может сохранять резервные копии по настройкам проекта; удаление записи не меняет политику резервного копирования провайдера.

## Проверка подключения

Тестовый запрос без заголовка ключа должен вернуть 401. Автоматические тесты проверяют аутентификацию, изоляцию пользователей, формирование серверных запросов, идемпотентность и ошибки хранилища:

```sh
npm test
```

При запуске проекта выполнена также проверка живой базы: добавление избранного, повторное добавление, отметка «отработано», удаление отметки, изоляция другого ID и удаление всех данных. Временные тестовые записи удалены.

## Перенос на другой проект Supabase

1. Примените `database/supabase.sql` в новом проекте (скрипт создаёт таблицу впервые).
2. Создайте новый случайный 32-байтовый секрет; сохраните его только в серверных секретах Vercel.
3. Обновите SHA-256 в `database/edge-function/auth.ts` и разверните файлы функции с именем `cs2-lineup-store`, собственной аутентификацией и `verify_jwt=false`.
4. Обновите `SUPABASE_URL` и `SUPABASE_STORE_SECRET` в Vercel и выполните redeploy.
5. Проверьте живое добавление / чтение / удаление. После успешного перехода удалите старую функцию или замените её digest, чтобы отозвать предыдущий ключ.

## Oracle — подготовленный вариант

Oracle сейчас **не подключён**: базы и учётных данных пока нет. [database/oracle.sql](../database/oracle.sql) содержит схему для Oracle Database 19c+ и примеры запросов с bind-параметрами.

Для будущего подключения понадобятся база Oracle, отдельный пользователь приложения с правами на `cs2_lineup_marks`, `ORACLE_USER`, `ORACLE_PASSWORD` и `ORACLE_CONNECT_STRING`. Сохраните их в серверных секретах Vercel. Для Autonomous Database проверьте режим TLS/mTLS: если требуется wallet, добавьте его через защищённое файловое хранилище, а не в Git. Разрешите сетевое подключение приложения к базе согласно настройкам Oracle.

Перед переключением нужно реализовать Oracle-адаптер интерфейса `getUserState`, `setFavorite`, `setMastered`, `deleteUserData` с пулом соединений и явным commit; проверить его на реальной базе и перенести данные. В репозитории нет имитации подключения Oracle, и Supabase продолжает быть единственным активным источником данных.
